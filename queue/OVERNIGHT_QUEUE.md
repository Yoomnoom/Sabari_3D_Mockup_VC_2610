## 작업 1. 단계 28 칼선 크롭 이미지 모드 + 띠 제거 + 영역 전체 조정 + 실제 디자인 검증
브랜치: task/1-dieline28. IMPLEMENTATION_PLAN.md에 칼선 단계 28이 이미 있으면 상태를 확인하고 남은 항목만 한다.
입력: inputs/20251027_김소연님_160_110_43_싸바리칼선_여분뚜껑_.ai, inputs/real_dieline_art.png(아트보드 전체 6209×4122px, 300dpi, 525.7×349.0mm, 뚜껑 십자형만 디자인, 몸통 쪽은 비어 있음), inputs/사바리_프로젝트.sabari(ZIP. images/dieline.png 2739×3343px가 사용자가 실제 올린 "칼선 외곽에 딱 맞게 크롭한 이미지"이므로 inputs/real_dieline_crop.png로 추출해서 쓰고 .sabari 원본은 수정하지 마라). 없는 파일이 필요한 검증은 건너뛰고 기록한다.
확인된 사실(다르면 실제 측정값을 우선하고 차이를 기록): 크롭 이미지는 칼선 외곽 232.0×283.0mm(약 11.81px/mm)에 정확히 맞고 재단 여분이 없으며 십자형 바깥은 투명이다. 현재 앱의 파라미터 칼선(재단 여분 기본 3mm)으로 분할하면 면 맞춤이 contain, 배율 0.97로 저장되어 5개 면 둘레에 면 바탕색 띠가 생긴다(2048px 텍스처 기준 상단 27~31px, 날개 31~44px). 크롭 이미지 좌상단 기준 칼선 좌표(mm): 중앙 패널 (57.30, 57.80) 117.4×167.4, 날개 깊이 38, 접어 넣는 폭 좌우 19.30·위아래 19.80. 아트보드 기준 뚜껑 패널은 (77.04, 91.84), 몸통 패널은 (330.27, 94.34) 112.4×162.4, 몸통 날개 깊이 43. 면 회전: 왼쪽 날개 시계 90°, 오른쪽 날개 반시계 90°, 위 날개 180°, 아래 날개 0°.
요구사항:
 A. 크롭 모드: 이미지 비율이 232:283(±1%)이고 십자형 바깥이 투명이면 "칼선 외곽 크롭 이미지 · 싸바리 160×110×43 인쇄소 칼선(2025-10-27)"을 자동 선택하고 재단 여분은 0으로 고정(입력 비활성)한다. 면 배치 데이터는 아트보드 모드와 같은 것을 재사용하고 원점 오프셋(19.74, 34.04)만 다르게 한다(중복 정의 금지). 업로드 화면에 "칼선 외곽에 맞게 자른 이미지입니다" 한 줄.
 B. 띠 제거: 크롭·아트보드 모드에서 분할이 만든 면 설정은 이미지가 면을 정확히 채우도록(단계 25의 늘이기 방식 재사용, scale 1.0, offset 0, contain+0.97이 저장되지 않게) 한다. 현재 contain+0.97이 저장되는 코드 경로와 원인을 기록한다. 파라미터 칼선 모드에서 이미지 비율이 칼선과 1% 넘게 다르거나 여백이 있어 보이면 "이미지에 여백이 있을 수 있습니다. 칼선 기준을 확인하세요" 안내를 표시한다.
 C. 영역 전체 조정: 분할 영역 조정 화면에 5개 영역을 한 번에 이동·확대하는 조정("영역 전체 이동/확대")을 추가한다(컨트롤 최소화, 조정 후 개별 영역 수정 가능, 결과는 .sabari에 저장·복원).
 D. 실제 이미지 검증(핵심): real_dieline_art.png(아트보드 모드)와 real_dieline_crop.png(크롭 모드) 각각을 올려 분할하고 수치와 스크린샷(verification-private/dieline-real2/: 윗면, 각 날개, 3/4, 영역 조정 화면)으로 기록한다. (1) 면 텍스처 둘레 5px가 면 바탕색 단색만으로 채워진 면이 없을 것, 둘레 픽셀 중 원본에서 온 비율을 면별로 기록. (2) 글자가 거울상이 아니고 각 날개 글자의 위쪽이 해당 날개가 붙은 패널 가장자리(박스 윗면 쪽)를 향할 것. (3) 패널과 날개 경계에서 그림이 이어지고 접어 넣는 영역이 면에 들어오지 않으며 프레임선이 면 가장자리에서 일정 간격에 나타날 것. (4) 아트보드 모드에서 몸통이 흰색으로 덮이지 않을 것. (5) 크롭 모드에서 영역 경계가 외곽선과 허용 오차 내일 것. 어긋나면 원인(좌표, 회전, 늘이기 비율, 비트맵 크기)을 분석하고 최소 수정, 수정이 크면 구현하지 말고 원인과 제안만 기록한다.
 E. .sabari 저장·열기, 임시저장, GLB·PNG 저장이 정상이고 GLB 텍스처 5장의 둘레에 띠가 없을 것. 큰 이미지(6209×4122px) 로딩 시간과 메모리를 기록한다. 빠른 검증 통과 후 병합한다. 실제 디자인의 시각 일치는 사용자 승인 대기로 남긴다.

## 작업 2. 단계 28c 투명 영역을 면 바탕색으로
브랜치: task/2-dieline28c.
문제: 칼선 이미지의 투명(비워 둔) 영역이 분할 시 불투명한 흰색으로 바뀌어 저장되고(사용자 크롭 이미지 분할 결과: 면 이미지 투명 픽셀 0개, 순백 픽셀 상단 595·앞날개 4,309·뒷날개 4,311·왼쪽 날개 819·오른쪽 날개 850개, GLB 텍스처에도 690/2,521/2,552/923/1,008개) 3D 면 가장자리에 흰 띠가 보인다. 기대: 비워진 영역은 그 면의 "면 바탕" 색으로 채워진다.
요구사항:
 1. 분할 처리에서 투명 영역을 평탄화(흰 배경 칠하기, JPEG 변환 등)하는 코드 경로를 찾아 원인을 기록하고 투명도를 보존하도록 고친다. 면 이미지는 .sabari에 PNG RGBA로 저장해 알파를 보존한다.
 2. 면 텍스처를 만들 때(화면, GLB, PNG 저장 공통 경로) 면 바탕색 위에 이미지를 합성한다. 완전 투명은 면 바탕색이 되고 반투명 가장자리는 알파에 맞게 섞인다(투명 픽셀의 숨은 RGB가 흰색이어도 번지지 않도록 premultiplied alpha 처리 확인). 면 바탕색을 바꾸면 즉시 갱신된다.
 3. 기존 규칙 유지(맞춤·배율·회전·반전, 이미지 없는 면의 면 바탕, 하단 몸통 빈 영역 미적용, 접어 넣는 영역 제외). 이전에 분할한 면 이미지에는 흰색이 박혀 있을 수 있으므로 분할 화면 안내 한 줄("이전에 분할한 면 이미지는 투명 영역이 흰색으로 저장되어 있을 수 있습니다. 칼선을 다시 분할하세요")과 "투명 영역은 면 바탕색으로 채워집니다" 한 줄을 넣는다. 기존 .sabari와 임시저장은 그대로 열린다.
검증: 합성 RGBA 칼선(바깥·모서리 알파 0에 숨은 RGB 흰색, 반투명 경계 몇 픽셀)을 분할·적용했을 때 알파 0 위치가 면 바탕색과 정확히 같고(오차 0) 원본에 없던 순백 픽셀이 없으며 반투명 경계가 알파 혼합값과 ±2 이내인지 면별로, 면 바탕색 28·3·128·255에서 기록한다. 실제 크롭 이미지(작업 1에서 추출한 real_dieline_crop.png)의 면별 흰 픽셀 수를 수정 전후 표로 기록하고 알파 0 영역과 겹치는 흰 픽셀이 0개여야 한다. 사용자 스크린샷 각도(박스 모서리에서 윗면과 날개가 만나는 곳) 전후 비교를 verification-private/dieline-real3/에 저장한다. .sabari 저장·복원, GLB 구조 불변(validator 0/0), PNG 색이 화면과 같을 것. 빠른 검증 통과 후 병합한다.

## 작업 3. 단계 28b 칼선 분할 화면 확대·이동
브랜치: task/3-dieline28b.

## 작업 5. 단계 30 각도 바 + 저장된 시점(.sabari 포함)
브랜치: task/5-view-presets. 작업 4가 BLOCKED/SKIPPED이면 현재 화면 구조에서 뷰어 영역 위치만 맞춰 진행하거나(가능하면) SKIPPED로 기록한다.
1) 축 기준 각도 바(뷰어 영역, 축 잠금 아래, 접이식 "미세 조절", 기본 접힘): 축 잠금이 켜지고 축이 정해졌을 때만 활성(아니면 비활성+"축을 먼저 정하세요"). 축을 정한 순간(또는 "기준 다시 잡기")의 박스 자세가 0°이고, 그 자세 quaternion과 축(국소 좌표)을 기준으로 저장한다. 컨트롤: 슬라이더 −180°~+180°(0.1° 단위), 숫자 입력, 버튼 −5° −1° +1° +5°, "0°로", "기준 다시 잡기". 각도 = 기준 자세에서 그 축 둘레로 돌린 값(절대값 방식, 누적 오차 없음). 마우스·터치 드래그와 Ctrl 스냅으로 같은 축을 돌리면 바 값이 실시간 갱신(±180° 정규화), 축을 바꾸면 새 기준과 바 0, 축 잠금을 끄면 비활성. 바 값은 파일에 저장하지 않는다.
2) 저장된 시점(뷰어 영역, 시점 버튼 아래): 슬롯 5개(상수 한 곳), 카드(썸네일 약 160px PNG, 이름 기본 "시점 1~5" 변경 가능, 카드 클릭으로 불러오기, "현재 시점 저장/덮어쓰기", 삭제). 기존 7개 시점 버튼은 고정 시점으로 유지. 저장 값: 박스 자세(quaternion), 카메라 위치·대상·확대(박스 맞춤 거리 대비 비율, 치수가 바뀌어도 같은 구도), FOV, 축 잠금 상태(켬/끔, 축 id)와 각도 바 기준, 뚜껑 열림 높이(mm). 색·이미지·치수는 저장하지 않는다. 불러오기는 저장값으로 복원(짧은 보간은 선택, 최종 값은 허용 오차 내 동일). 외부 GLB 보는 중에는 비활성. 충돌하지 않으면 Alt+1~5 단축키(충돌하거나 단축키 설정이 꺼져 있으면 만들지 않음/동작 안 함).
3) .sabari에 선택 필드 viewPresets(슬롯 번호, 이름, 값, 썸네일 파일 경로)를 추가한다. 썸네일은 ZIP 안 작은 PNG로 두고 project.json에 base64를 넣지 마라. schemaVersion을 한 단계 올리고, 필드가 없는 기존 파일은 빈 슬롯으로 열리며 미래 버전은 기존 방식대로 오류 메시지를 보인다. 임시저장에도 저장·복원한다. 슬롯 추가·덮어쓰기·이름 변경·삭제는 프로젝트를 "변경됨" 상태로 만들고 실행 취소 대상은 아니다. GLB 노드 변환은 영향받지 않는다.

## 작업 9. 바닥 그림자 (켜기/끄기 가능)
브랜치: task/9-floor-shadow (integration에서 분기, 병합 규칙은 공통 규칙대로). 순서: 작업 8 뒤에 진행한다.
사용자 요구: 조명(음영) 영역에 바닥 그림자도 함께 있어야 하고, 그림자는 사용자가 켜고 끌 수 있어야 한다. 현재 "조명 (음영)" 영역은 면 명암(음영 세기 슬라이더)만 있다.
요구사항:
1. 조명 영역에 "바닥 그림자 보기/숨기기" 토글(텍스트 라벨 병행, aria-pressed, 색만으로 구분하지 않음)을 추가한다. 기본값은 꺼짐이고 꺼진 상태의 화면은 변경 전과 완전히 같아야 한다. 켜면 아래 조절 항목이 나타나고 끄면 숨긴다: 세기(0~100%, 기본 40%), 부드러움(0~100%, 기본 50%), 빛 방향(좌우 0~360°, 높이 20~80°, 기본값은 박스 오른쪽 위 앞쪽에서 비추는 값, 숫자 입력 병행, "기본값 복원" 버튼).
2. 구현: 박스 바닥 높이에 보이지 않는 바닥판을 두고 그림자만 반투명으로 그리는 방식(ShadowMaterial 또는 동등한 방식)을 기본으로 한다. 바닥판 자체는 보이면 안 된다. 박스 표면의 색 렌더링(색 정확도 단계의 셰이더, 음영 세기)은 변경하지 않는다. 그림자는 박스 색을 어둡게 하거나 밝히지 않고 바닥에만 떨어진다. 구현 방식(그림자 맵, 부드러움 처리 방식)은 직접 정하고 이유를 기록한다.
3. 바닥은 월드에 고정이고 박스(pivot 회전)와 카메라가 움직여도 그림자가 박스를 올바르게 따라간다. 박스가 놓이는 높이(바닥 접촉 위치)는 코드 한 곳에서 계산한다(눕힘, 세움, 뒤집힘 자세, 뚜껑 열림 높이 포함). 뚜껑을 열면 열린 뚜껑의 그림자도 변하고, 뚜껑·몸통 표시 숨김 상태도 그림자에 반영한다.
4. 아래 시점이나 뒤집힌 자세에서 바닥판이 시야를 가리거나 이상한 선이 생기지 않아야 한다.
5. PNG 저장(흰색, 투명, 화면 그대로)에 그림자가 포함된다. 투명 PNG에서는 그림자가 반투명 알파로 저장되고 그림자 가장자리에 흰선·흰 테두리가 생기지 않아야 한다(투명 PNG를 마젠타·검정·흰색에 합성해 가장자리 밝기·알파를 측정해서 기록). 그림자는 GLB 내보내기에 절대 들어가지 않고(바닥판 제외, 노드·메시·재질 불변, validator 오류·경고 0) .sabari·임시저장에는 저장하지 않는다(브라우저 localStorage에만 기억, 파일 형식 변경 없음).
6. 성능: 그림자를 켜도 회전이 끊기지 않게 한다(그림자 맵 크기와 갱신 방식, 헤드리스 환경에서 측정한 프레임 시간 기록). 실제 GPU 성능은 미검증으로 남긴다.
7. GLB 열기(뷰어 영역)로 연 GLB에서도 같은 그림자 설정을 쓸 수 있게 한다(템플릿 GLB와 외부 GLB 모두 바닥 위치를 바운딩 박스로 계산).
8. 기본 화면의 컨트롤 줄 수는 토글 1줄만 늘리고, 조절 항목은 토글을 켰을 때만 나타난다. UI 문구는 한국어. 사용방법.md에 "그림자는 화면과 PNG에만 반영되고 GLB에는 들어가지 않는다"를 한 줄로 적는다.
검증: 켜기/끄기(끈 상태 화면이 변경 전과 같은지 픽셀 비교), 세기·부드러움·방향 변경에 따른 그림자 변화, 눕힘·세움·뒤집힘 자세와 뚜껑 열림에서 그림자가 박스 바닥과 접하는지(접촉 위치 수치), 하단·뚜껑 숨김 반영, 박스 색 정확도 불변(색 정확도 단계의 정면 색 표를 그림자 켠 상태에서 다시 측정해 오차 0), 투명 PNG의 그림자 알파와 가장자리 흰선 측정, 아래 시점·뒤집힌 자세에서 바닥판이 보이지 않는지, GLB에 바닥판·그림자가 없고 validator 0/0, .sabari·임시저장 영향 없음, 새로고침 후 설정 복원, 프레임 시간 기록, 기존 회귀(Vitest, pytest, 빌드, e2e 20개, 36조합). 빠른 검증 후 병합하고 deploy/clean-candidate를 갱신한다. 시안이 보이는 비교 이미지는 verification-private/에만 저장한다.
