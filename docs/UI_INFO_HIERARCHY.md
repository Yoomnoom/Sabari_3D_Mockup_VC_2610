# UI 정보 위계 원칙 (작업 32A, 제안 문서)

이 문서는 설명문·안내·경고를 정리하는 원칙이다. **기능, 문구의 의미, 설정값, 버튼, 컨트롤은 삭제하지 않는다.** 새 UI 문구와 컨트롤을 추가하는 작업은 이 문서를 따른다. 전수 조사 표는 `verification/ui-info/inventory.md`에 있다.

## 1. 목표
1. 사용자가 각 구역에서 해야 할 행동이 먼저 보인다.
2. 긴 설명 때문에 버튼과 핵심 컨트롤이 아래로 밀리거나 묻히지 않는다.
3. 전문 안내와 경고는 보존하되 단계적으로 노출한다.
4. 데스크톱과 모바일(작업 시트)이 같은 정보 구조를 쓴다.

## 2. 구역 순서
제목 → 현재 설정값 또는 핵심 컨트롤 → 실행 버튼 → (필요하면) 짧은 안내 한 줄 → 상세는 "자세히 보기" 또는 제목 옆 `?`.
설명을 버튼 아래로 옮기면 오해하거나 위험한 경우에만 설명을 버튼 위에 두고 1~2줄로 요약한다.

## 3. 문구 4분류
| 분류 | 기준 | 노출 |
|---|---|---|
| a. 핵심 안내 | 실행 전에 반드시 알아야 하는 것 | 항상, 최대 1~2줄, 연한 회색(명도 대비 4.5:1 이상) |
| b. 상세 설명 | 빈도가 낮거나 전문적인 설명 | 기본 접힘. "자세히 보기 ▾" 하나로 통일, 열고 다시 접을 수 있음 |
| c. 조건부 안내·경고 | 비율 불일치, 지원하지 않는 형식, PNG 크기 초과, 외부 GLB 제한, 하단 이미지 삭제, 재단 여분·치수 문제, 입력 오류 | 해당 상황에서만(정상일 때 공간을 차지하지 않음) |
| d. 현재 상태 | 이미지 없음, 외부 GLB 보는 중, 자동 저장됨, 배경: 흰색, PNG: 2배 | 설명문이 아니라 짧은 배지·한 줄 상태값 |

조사 결과(2026-10-06, 안내 요소 60개): a 16, b 17, c 10, d 17. 항상 노출되는 설명은 디자인 탭 5개(213자), 박스 탭 2개(108자), **보기 탭 6개(381자)**, 내보내기 탭 3개(92자). 보기 탭이 가장 길다.

## 4. 알림 4단계
정보(회색·연한 파랑), 주의(연한 주황), 오류(연한 빨강), 성공(연한 초록). 색만으로 구분하지 않고 아이콘과 글자("주의", "오류")를 함께 쓴다. 모든 메시지를 주황색으로 만들지 않는다.
작업 29의 알림 영역(`notify.ts`)은 현재 `NoteKind = 'ok' | 'error'` 두 가지다. 확장 방식: `NoteKind`에 `info`·`warn`을 더하고 종류 → (아이콘, 글자 라벨, 색 토큰) 표 하나로 렌더링한다. 최근 알림 목록(`NoteRecord`)에도 같은 라벨을 남긴다. 기존 호출은 `error`→오류, `ok`→성공으로 그대로 동작한다.

## 5. 버튼 위계
| 역할 | 스타일 |
|---|---|
| 핵심 행동 | 주황 채움. 한 카드·구역에 원칙적으로 하나 |
| 보조 행동 | 흰 배경 + 회색 테두리 |
| 취소·닫기 | 중립 보조 |
| 삭제·초기화 | 평소 회색 또는 텍스트 버튼. 삭제를 확정하는 단계만 빨간 위험 버튼 |
| 토글 켜짐(aria-pressed) | 어두운 채움 |
| 선택됨 | 주황 윤곽 |
| 비활성 | 밝은 회색 + 이유 툴팁 |

토글·선택 상태를 주황 채움 규칙으로 지우지 않는다. 버튼 이름과 기능은 유지하고 새 버튼을 만들지 않는다.
현재 앱의 실제 패턴(조사): 탭 패널 안의 `primary`(주황 채움) 버튼은 디자인 탭의 "이미지 선택" 하나뿐이고 박스·보기·내보내기 탭에는 없다(내보내기 탭의 대표 행동 PNG/GLB 저장은 채움이 아님). 칼선 분할·저장 이름·가져오기 대화상자는 대화상자마다 `primary` 하나다. → 정의와 다른 곳: 내보내기 탭 대표 행동, 삭제 버튼("이미지 제거", "삭제")의 평소 스타일(32B에서 표로 확정).

## 6. 긴 패널
- 패널 내부만 스크롤한다. 페이지 전체 스크롤과 3D 캔버스 높이는 바꾸지 않는다.
- 탭의 대표 행동이 아래로 사라지면 하단 sticky 실행 영역(대표 행동 하나 또는 반드시 함께 써야 하는 묶음)을 둔다.
- 아래에 내용이 더 있음을 스크롤바 또는 하단 페이드로 표시한다.
- 쌓임 순서: 맨 아래 = 작업 29의 고정 상태줄, 그 위 = sticky 실행 영역.

## 7. 문장 규칙
한 문장에 한 가지 내용 · 가능하면 35자 이내(의미가 약해지면 예외) · 사용자가 할 행동을 먼저 · 화면에서 확인할 수 있는 결과로 설명 · 같은 내용을 여러 구역에 반복하지 않음 · "~됩니다/~할 수 있습니다" 반복 줄이기 · 경고는 문제와 해결 방법을 함께 · 버튼 이름을 설명문에서 반복하지 않음.
예: "배경과 크기를 설정한 뒤 PNG로 저장하세요." / 기본 "디자인 가이드용이며 제조용 칼선이 아닙니다." + 상세 "실제 제작에는 인쇄소에서 제공한 최종 칼선 템플릿을 사용하세요." / "임시저장은 현재 브라우저에만 보관됩니다."
**"디자인 가이드용, 제조 칼선 아님"은 삭제 금지이며 한 줄은 항상 노출한다.**

## 8. "자세히 보기" 규격
`details/summary`로 통일한다(이미 칼선 분할 안내가 이 방식). Enter·Space로 열고 닫히며, 터치 영역은 44px 이상이다. 같은 구역에 여러 개를 나열하지 않고 제목 옆 `?` 하나로 묶는 안을 우선 검토한다. 상태는 `aria-expanded`(details는 기본 제공)로 전달한다.

## 9. 하지 않는 것
기능 삭제, 설정값·기본값 변경, 버튼 기능·이름 변경, 탭 순서·면 이름 변경, 전문 용어의 의미 변경, 경고 삭제, 3D 영역 축소, 회전·축 잠금·저장·칼선·PNG·GLB 로직 변경, 새 기능 추가, 저장 형식 변경, 관련 없는 리팩터링.

## 10. 이후 UI 작업 지침 (이미 병합된 작업 26·27·28·30·31 포함)
- 새 안내는 한 줄. 긴 설명은 `details`로. 조건부 경고는 해당 상황에서만(예: 가져오기의 "면 크기가 달라…", 칼선 방향 안내).
- 한 구역에 주황 채움 버튼은 하나. 작업 26 레이어 구역의 "바탕 이미지 추가"는 보조 스타일 유지.
- 상태 문구(`role="status"`)와 경고(`role="alert"`)를 구분한다.
